# sql2widget 질문 분리·경로 순서 작업 기록

기준일: 2026-10-15. 상태: 구현 완료·검증 대기.

## 요청과 변경

사용자는 복수 질문을 하위 요청으로 나누고 각 질문의 실제 선택 경로를 확인하기를 요청했다. 실행 단계는 UI에서 접고 펼칠 수 있어야 한다. 이후 같은 경로가 여러 번 선택될 수 있으므로 중복 제거 나열 대신 번호·화살표로 실행 순서를 유지하도록 정했다.

자동 계획 프롬프트에 의미별 분리·같은 경로 질문 유지·비교/조건 보존·선행 결과 의존 규칙을 추가했다. 다단계 질문 누락은 오류로 처리한다. 실행 처리 내역은 단계마다 하위 질문·예상/실제 경로·분류 방식·재계획 차수를 보존한다. 단계 UI는 기본 접기와 질문/경로 상세를 유지한다.

## 작성한 회귀 검사와 다음 검증 대상

- `backend/tests/test_question_plan.py`: 긴 하위 질문의 끝 조건 보존·다단계 질문 누락 거부.
- `backend/tests/test_question_steps.py`: 여러 하위 질문과 경로 복귀 순서·앞 결과 문맥·재계획·되묻기 연결. SQL 앱은 부분 실패의 확정 경로도 확인.
- `backend/tests/test_chat_trace.py`: 저장용 처리 내역의 실제 질문·실행 순서·재계획 연결 보존.
- `frontend/tests/chatTrace.test.js`: A→B→A·같은 경로 연속 실행·미기록/과거 처리·재계획 질문 표시.
- 프런트 Vite 빌드와 실제 화면 접기·펼치기/줄바꿈, 문서 생성 동기화 검사는 다음 검증 대상이다.

## 이번에 실행한 범위와 남은 확인

소스·변경 diff를 읽어 검토하고 `python3 scripts/render_docs.py`로 문서 HTML을 생성했다. 테스트·검증용 빌드·브라우저 검증·`render_docs.py --check`·실모델 호출은 실행하지 않았다. 사용자가 질문 분리 구현 뒤에 테스트하기로 한 순서를 따른다. 위 테스트는 대역 기반이며 실모델의 의미별 분리 정확도를 입증한 결과가 아니다. 커밋·푸시·배포는 하지 않았다.
