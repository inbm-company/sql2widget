# sql2widget 다시 생성·계속하기·메시지 개별 삭제

기준일: 2026-10-15. 구현 완료·검증 대기.

사용자는 답변·위젯·처리 내역 뒤의 다시 생성, 중지된 요청의 채팅 기록 기반 계속하기, 질문과 답변 각각의 개별 삭제를 요청했다. 최초의 질문/답변 묶음 삭제 해석을 사용자가 바로잡아 개별 메시지 삭제로 수정했다. 기존 사이드바 채팅방 삭제는 그대로다.

질문 아래에는 질문 삭제, 각 답변 아래에는 다시 생성/계속하기와 답변 삭제를 배치한다. 질문을 지워도 연결된 답변은 남고, 답변을 지워도 질문과 다른 답변은 유지한다. 과거 답변은 질문 삭제 전에 연결 ID를 고정해 다른 질문으로 재연결되지 않도록 한다. 질문이 삭제된 답변은 독립적으로 표시하고 삭제할 수 있지만 원래 질문으로 다시 생성할 수는 없다.

삭제 API는 `DELETE /api/conversations/{conversation_id}/messages/{message_id}`이며 소유자·테넌트를 확인하고 정확히 한 ID만 삭제한다. 질문 삭제 후 늦은 새 응답 저장을 차단한다. SQL 앱은 선택한 메시지의 벡터 사본만 정리하고 삭제할 답변을 참조하던 과거 Stage 위젯의 조회 참조를 보존한다. 실제 사용자 데이터를 삭제하지 않았다.

재생성/계속하기는 원래 질문을 재사용한다. 최신 재생성 대안과 후속 계속하기 답변으로 다음 문맥을 구성하며 이전 답변은 화면에 보존한다. 미완료 상태와 최신 응답 ID를 사용자 meta에 저장해 새로고침·동시 요청을 처리한다.

## 작성한 검증 대상

- `backend/tests/test_chat_actions.py`: 원문 재사용·질문 중복 없음·재생성/계속하기 문맥·질문/답변 삭제 API의 권한/범위.
- `backend/tests/test_chat_turn_storage.py`: 로컬 PostgreSQL 트랜잭션에서 질문만 삭제/답변 보존, 답변만 삭제/질문·다른 답변 보존, 과거 연결 유지·늦은 저장 차단·프로젝트 자원 보존. SQL 앱은 선택 메시지의 벡터 삭제 실패 롤백과 과거 Stage 참조 보존 포함. 테스트 데이터는 기존 fixture에서 롤백한다.
- `frontend/tests/chatTurns.test.js`: ID 기반 연결·같은 본문 구분·재생성 중복 방지·질문 삭제 후 답변 독립 표시·다른 답변 보존.
- Vite 빌드·문서 `--check`·브라우저의 개별 삭제/확인 취소/다시 생성/계속하기는 아직 실행하지 않았다.

## 수행한 범위

소스와 diff를 읽고 문서 HTML을 생성했다. 테스트·검증용 빌드·브라우저·실모델 호출은 미실행이다. 커밋·푸시·배포를 하지 않았다. 새 DB 마이그레이션·의존성은 추가하지 않았다.
