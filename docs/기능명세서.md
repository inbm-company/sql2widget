## 1. 제품 개요

### 1.1 한 줄

비기술 사용자가 자연어로 고객 DB를 조회하고, 결과를 허용된 위젯으로 받은 뒤, **대화마다 1개**인 Stage에 꽂아 배치·저장한다.

### 1.2 성공 정의

질문에 맞는 위젯이 채팅에 나오고, 사용자가 일부를 Stage에 핀한다. 완성된 공유 대시보드 템플릿을 자동 생성하는 것은 목표가 아니다.

### 1.3 데모 청중 (동등)

| 연결 ID | 이름 | 데이터 |
|---------|------|--------|
| `dbconn_demo` | SOC | 서버, 공격, 인시던트, 취약점, 차단 IP |
| `dbconn_global` | Global Sales | 지역, 제품, 월별 매출 |

### 1.4 범위

**포함**

- 로그인 / 토큰 갱신
- 대화 CRUD, Mock(또는 LLM 폴백) 채팅
- Artifact 위젯 렌더, SQL 미리보기(허용 컴포넌트)
- Stage DnD·이동·리사이즈·자동 저장
- 연결 관리·테이블 권한(관리자)
- Viewer 전용 보기 화면

**제외 (이후)**

- 운영 배포, 실 RAG 고도화
- 완성 대시보드 템플릿
- 카탈로그 밖 차트 자유 생성
- 테넌트 다중 운영 콘솔

## 2. 용어

| 용어 | 의미 |
|------|------|
| Artifact | 한 번 답변에 묶인 위젯 집합. `type`은 `widget` / `dashboard` / `report` |
| Widget | 허용 컴포넌트 하나. `widget_id`, `component`, `title`, `props`, 선택 `sql` |
| Stage | 대화당 1개 핀보드. 위젯 레이아웃을 저장 |
| Connection | 테넌트에 등록된 고객 PostgreSQL. 채팅 시 SELECT 대상 |
| Furniture | 에이전트가 내는 닫힌 카탈로그 JSON. 모르는 키/타입은 버림 |

## 3. 사용자와 권한

### 3.1 역할

| 역할 | 시드 계정 | 할 수 있는 일 |
|------|-----------|----------------|
| `admin` | `admin@example.com` / `demo-password` | 채팅, Stage 편집, 대화 생성·이름변경·삭제, Admin(연결·권한), Viewer 열기 |
| `user` | (시드 권한 행만 존재, 로그인 계정은 없음) | API상 일반 사용자. 연결 생성·권한 변경·SQL 프리뷰는 불가 |
| `viewer` | `viewer@example.com` / `demo-password` | 본인 대화 목록·메시지·Stage **조회만**. 채팅·DnD·리사이즈·대화 생성/수정/삭제 불가 |

공통: 대화는 `tenant_id` + `user_id`로 격리된다. 남의 대화 ID를 알아도 404.

### 3.2 화면 권한 (프론트)

| 동작 | admin | viewer |
|------|-------|--------|
| New chat | O | X |
| 질문 전송 / 샘플 질문 | O | X |
| 위젯 드래그·스크린에 추가 | O | X |
| Stage 이동·리사이즈·삭제 | O | X |
| Stage 패널 숨기기 | O | 패널 숨김(편집 없음) |
| Admin 패널 | O | X |
| Open viewer `/c/{id}/view` | O | O |
| 연결 선택 | O | O (조회용, 채팅 불가) |

## 4. 시스템 구성

```
브라우저 (5173)
    → FastAPI (/api, 기본 8010)
        → 서비스 DB (users, conversations, stages, connections, …)
        → 고객 DB (읽기 전용 SELECT)
```

- 프론트: Vite, React JavaScript, `useSWR` + `useStore`, Provider/`SWRConfig` 없음
- 백엔드: FastAPI, psycopg, ORM 없음
- 로컬 기동: Docker Compose

## 5. 기능 명세

### F-01 로그인

| 항목 | 내용 |
|------|------|
| 액터 | 모든 역할 |
| 입력 | email, password |
| 처리 | 이메일 소문자·trim. 비밀번호 검증. JWT access + refresh 발급 |
| 출력 | `access_token`, `refresh_token`, `user { id, email, role, tenant_id }` |
| 저장 | 브라우저 `localStorage` (`agent4any_access`, `agent4any_refresh`) |
| 실패 | 401 Invalid credentials. 화면 오류 문구 |

Access 기본 30분, Refresh 기본 14일. API 401 시 refresh 1회 후 재시도. 실패 시 토큰 삭제.

### F-02 세션 복원

앱 시작 시 access가 있으면 `GET /api/auth/me`. 성공하면 워크스페이스, 실패하면 로그인.

### F-03 대화 목록

- `GET /api/conversations`: 내 대화, 최근 사용 순
- 사이드바에서 선택. 호버 시 이름 변경·삭제(편집 가능 역할만)

### F-04 대화 생성

- `POST /api/conversations` `{ title }`
- UI 기본 제목: `New Chat`
- viewer는 버튼 비활성. 빈 화면의 New chat은 admin만 의미 있음(viewer는 기존 대화만)

### F-05 대화 이름 변경 / 삭제

- `PATCH` 제목, `DELETE` 대화
- 삭제 시 해당 대화의 메시지·Stage도 함께 제거(저장소 cascade)
- 활성 대화를 지우면 목록의 다음 대화로 이동

### F-06 대화 상세

- `GET /api/conversations/{id}`
- 메시지 배열. assistant 메시지는 `artifact` JSON을 포함

### F-07 고객 DB 선택

- 사이드바 Database 셀렉트
- 목록: `GET /api/database-connections` (테넌트 공유)
- 기본값: 목록 첫 항목
- `dbconn_global`이면 Global 샘플 질문, 그 외 SOC 샘플 질문

### F-08 채팅 (핵심)

| 항목 | 내용 |
|------|------|
| 입력 | `conversation_id`, `message`, `connection_id`(선택) |
| 처리 | 1) user 메시지 저장 2) 첫 문장으로 제목 갱신 3) 에이전트 실행 4) assistant + artifact 저장 |
| 출력 | user/assistant 메시지, artifact, meta(`provider`, `connection_id`) |
| UI | Enter 전송, Shift+Enter 줄바꿈. 실패 시 입력 복원 + 오류 문구 |
| 타임아웃 | 프론트 채팅 요청 150초 (실 LLM 최대 60초 + SQL/수정 재시도 여유) |

**에이전트 경로**

1. `LLM_PROVIDER=mock`(기본) 또는 키 없음 → Mock 키워드 매칭
2. 실 LLM 설정 시 플랜 JSON → SELECT 실행 → props 변환. 키가 없는 경우에만 Mock을 사용하며, 실 LLM 오류는 화면에 반환
3. 사용량은 `llm_usage`에 기록(실모델 경로)
4. 실 LLM에는 선택한 연결의 역할별 허용 테이블에 한해 테이블·컬럼·타입·PK/FK 관계를 전달한다. 실제 데이터 행과 연결 비밀번호는 전달하지 않는다.

**Mock 매칭 (SOC, `dbconn_demo`)**

| 질문 힌트 | Artifact 요지 |
|-----------|----------------|
| 보고서 / report / SOC | 요약 마크다운 + KPI + 공격 표 + 인시던트 + 취약점 |
| 유형 / 비중 / pie | PieTable 공격 방법 |
| 심각도 / severity | KPI 3 + 집계 표 |
| 추이 / 7일 / trend | LineChart |
| 취약점 / CVE | DataTable |
| 차단 / blocked / IP | DataTable |
| 자산 / 위험 (또는 서버이되 공격 없음) | RankList + DataTable |
| 공격 / attack | BarTable + 해결 방안 + 출처 |
| 인시던트 | DataTable |
| 그 외 | 샘플 질문 안내 MarkdownBlock |

**Mock 매칭 (Global, `dbconn_global` 또는 `monthly_sales` 허용)**

| 질문 힌트 | Artifact 요지 |
|-----------|----------------|
| 보고서 / report / 글로벌 | 총매출 KPI + 지역 BarTable + 제품 PieTable + 월별 LineChart |
| 제품 / 비중 / pie | PieTable |
| 추이 / 12개월 | LineChart |
| 지역 / 매출 / sales | BarTable |
| 그 외 | Global 샘플 안내 |

**SQL 규칙 (모든 경로)**

- `SELECT` 또는 `WITH`만. 다중 문장 금지
- INSERT/UPDATE/DELETE/DDL/권한/락 절 금지
- `FROM`/`JOIN` 테이블은 역할별 허용 목록에 있어야 함
- 행 상한 1000

연결이 없거나 권한 테이블이 비면 SOC 기본 테이블 집합으로 폴백.

**로컬 일반 DB 예제**: Docker Compose는 `dbconn_northwind`(Northwind-style PostgreSQL)를 함께 시드한다. `customers`, `orders`, `order_details`, `products` 등의 스키마는 Gemini가 런타임에 읽는 메타데이터로 전달되므로, SOC/Global 전용 키워드 규칙 밖의 일반 질의도 실 LLM 경로에서 처리한다. 키가 없는 Mock 경로는 기존 SOC·Global 데모 규칙을 유지한다.

### F-09 Artifact 표시

- 미리보기 / JSON 토글
- 각 위젯: 제목, 렌더러, (가능하면) SQL 보기
- SQL 보기 가능 컴포넌트: KPI·표·순위·차트·필터·스파크·PieTable·BarTable
- Markdown / SourceList는 SQL 없음
- 미리보기 카드는 grab. viewer는 드래그·추가 버튼 없음

### F-10 Stage에 위젯 추가

경로:

1. 채팅 카드를 Stage로 드래그 (`application/x-agent4any-widget`)
2. 카드의 추가 버튼

처리: `POST .../stage/widgets`

- `component`가 화이트리스트 밖이면 **400** (채팅 sanitize의 DataTable 폴백과 다름)
- `layout { i, x, y, w, h }` 기본 4×4
- `source_widget_id` / `source_artifact_id`로 출처 추적

### F-11 Stage 배치

- 대화당 Stage 1행. 없으면 GET 시 생성
- `react-grid-layout`. 이동·리사이즈 후 **디바운스 저장**
- 전체 교체: `PUT .../stage` `{ widgets: [...] }`
- 단건 수정: `PATCH` title / props / layout
- 삭제: `DELETE`
- 새로고침 후 복원
- 빈 Stage: “대화의 결과 위젯을 여기로 드래그하세요” (viewer: “배치된 위젯이 없습니다.”)
- 저장 상태 표시: saving / saved / error (편집 역할만)

### F-12 Viewer 화면

- 경로: `/c/{conversationId}/view`
- Stage만 전체 화면. 읽기 전용(드래그·리사이즈 없음)
- 헤더: 뒤로, 대화 제목, 기간 pill(표시용), 사용자 이메일

### F-13 관리자 — 연결

액터: `admin`만. 그 외 403.

| API | 기능 |
|-----|------|
| `GET /api/database-connections` | 테넌트 연결 목록 (비밀번호 비노출) |
| `POST /api/database-connections` | 연결 추가 (host, port, db, user, password, sslmode) |
| `POST .../test` | `SELECT 1` 연결 테스트 |
| `GET .../tables` | information_schema 베이스 테이블 목록 |
| `POST .../preview-sql` | 검증된 SELECT 실행 (admin) |

### F-14 관리자 — 테이블 권한

- `GET /api/table-permissions?connection_id=`
- `PUT /api/table-permissions` `{ connection_id, role, tables }`
- 시드: `admin` / `user` / `viewer` 각각 SOC·Global 허용 테이블 설정
- 채팅 SELECT는 이 목록으로 제한

### F-15 헬스

`GET /api/health` → `{ ok, provider, effective_provider }` (인증 없음)

## 6. 허용 위젯 카탈로그

서버 `ALLOWED_COMPONENTS`. 목록 밖 이름은

- **채팅 artifact**: `DataTable`로 치환. 표 형태가 없으면 안내 행
- **Stage 저장**: 거부 (400)

| 컴포넌트 | 용도 | 대표 props |
|----------|------|------------|
| `KpiStat` | 단일 수치 | label, value, unit |
| `DataTable` | 표 | columns, rows |
| `RankList` | 순위 | items[{ rank, label, value, meta }] |
| `BarChart` | 막대 | categories, series |
| `LineChart` | 추이 | series[].points[{ x, y }] |
| `PieChart` | 비중 | slices[{ label, value }] |
| `MarkdownBlock` | 설명·보고서 | markdown, citations |
| `SourceList` | 문서 출처 | sources |
| `FilterBar` | 필터 UI | (카탈로그 예약) |
| `KpiSparkline` | KPI+스파크 | value + points |
| `PieTable` | 파이+표 | slices, columns, rows |
| `BarTable` | 막대+표 | categories, series, rows |

차트 렌더: Recharts (`WidgetRenderer.jsx`).

## 10. 대표 시나리오 (인수)

### S-01 SOC 질문 → 핀

1. admin 로그인
2. New chat, Database = SOC 데모
3. “공격 유형별 비중을 보여줘.”
4. PieTable이 채팅에 나타남
5. Stage로 드래그 → 새로고침 후 유지

1. Database = Global Sales
2. “지역별 매출 순위를 보여줘.”

### S-03 Viewer

1. viewer 로그인
2. 입력창 없음, Stage 이동 불가

preview-sql 또는 에이전트 SQL에 `DELETE` → 400 / QueryError. 고객 DB 데이터 불변
