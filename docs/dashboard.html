개요 & 공통 규칙

기준일 2026-09-21 · 원문 AGENTS.md / CLAUDE.md(루트, 코딩 에이전트 자동 로드)

비기술 사용자가 자연어로 고객 DB(SOC 보안 / Global Sales)를 조회하고, 결과를 허용된 위젯(차트·표·KPI 등)으로 받은 뒤, 프로젝트마다 1개인 Stage(핀보드)에 배치·저장하는 에이전트 MVP다. 완성된 공유 대시보드 템플릿을 자동 생성하는 것은 목표가 아니다.

주요 기능 개요

기능한 줄 설명
로그인/세션이메일·비밀번호 로그인, JWT access+refresh, admin/viewer 역할 구분
프로젝트·대화프로젝트(최상위 단위) 아래 여러 대화(conversation)를 생성·이름변경·삭제
채팅(에이전트)자연어 질문 → 실 LLM(OpenAI-compatible/Gemini)이 SELECT 계획을 세워 실행 → 위젯 Artifact 반환. AI 키가 없거나 호출이 실패하면 추측하지 않고 에러를 그대로 반환
Artifact/위젯 표시채팅 응답의 위젯을 미리보기·JSON 토글로 표시, 가능한 경우 실행된 SQL도 표시
Stage 배치채팅 카드를 드래그하거나 버튼으로 프로젝트의 Stage(핀보드)에 추가, 자동 저장·새로고침 후 복원
Viewer 전용 화면/p/{projectId}/view — 채팅·편집 없이 Stage만 읽기 전용으로 표시
관리자DB 연결/테이블 권한/브라우저별 AI 설정

데모 데이터셋은 두 개이며 동등하게 취급한다: dbconn_demo(SOC 보안), dbconn_global(Global Sales). 로컬 개발용으로 Northwind, SKAX NMS 샘플 DB도 함께 시드된다.

공통 확정 규칙

제품 규칙

  1. 동등한 데모 두 세계 — SOC 보안과 Global Sales는 하나가 메인이고 다른 하나가 곁다리인 관계가 아니다.
  2. 핀보드지 포스터가 아니다 — 성공은 질문에 맞는 위젯이 채팅에 나오고 사용자가 몇 개를 Stage에 꽂는 것.
  3. 카탈로그 가구, 사용자 배치 — 에이전트는 후보 위젯을 제안하고, 배치는 사용자가 한다.
  4. 닫힌 타입, 열린 값 — 차트 종류·레이아웃 문자열·색상을 에이전트가 지어내지 않는다.
  5. 프로젝트 스코프 — Stage는 프로젝트당 1개. 전역 대시보드 라이브러리가 아니다.

기술/아키텍처 규칙

  • 백엔드: Python, FastAPI, psycopg, 순수 SQL. ORM 없음.
  • 프론트: Vite, React, JavaScript. TypeScript 없음.
  • 상태관리 3원칙: 서버 fetch → useSWR / 전역 UI 슬롯 → useStore(Provider 금지) / 입력·드래그 중 로컬 상태 → useState
  • 고객 DB는 읽기 전용 SELECT만.
  • 위젯 컴포넌트 이름은 서버 화이트리스트 검증.
  • 채팅 응답은 항상 실 LLM 호출로만 만든다(OpenAI-compatible). 키가 없거나 호출이 실패하면 키워드 매칭 등으로 추측해서 대신 답하지 않고 에러를 그대로 반환한다.

보안/운영 규칙

  • 서비스 DB와 고객 DB를 같은 커넥션·같은 쿼리 경로로 섞지 않는다.
  • 모델이 서비스 DB에 임의 SQL을 실행하게 하지 않는다.
  • 고객 DB 비밀번호·API 키를 로그에 남기지 않는다.
  • 화이트리스트 밖 컴포넌트 이름을 새로 만들지 않는다.
  • 근거 없는 해결 방안을 지어내지 않는다.
  • 합의 없이 DML, ORM, TypeScript, SWR Provider 패턴을 도입하지 않는다.

F-01 로그인

액터모든 역할
입력email, password
처리이메일 소문자·trim 후 조회 → argon2로 비밀번호 검증 → JWT access + refresh 발급
출력access_token, refresh_token, user { id, email, role, tenant_id }

  • Refresh 토큰 만료: 기본 14일(JWT_REFRESH_DAYS)

F-02 세션 복원 / 토큰 갱신

  • 앱 시작 시 access_token이 있으면 GET /api/auth/me 호출 → 성공하면 워크스페이스, 실패하면 로그인 화면.
  • API 응답이 401이고 refresh 토큰이 있으면 /api/auth/refresh로 1회 갱신 후 원 요청을 재시도한다. 동시 다발 401도 refresh 호출은 1회로 합쳐진다.
  • 갱신도 실패하면 토큰을 지우고 로그인 화면으로 돌아간다.
  • 일반 API 요청 타임아웃은 15초, /api/chat만 150초(실 LLM 응답 + SQL 재시도 여유).

F-03 프로젝트·대화 목록

  • GET /api/projects — 로그인 사용자의 프로젝트를 updated_at DESC, created_at DESC 순으로 반환.
  • 프로젝트를 펼치면 GET /api/conversations?project_id={id}로 해당 프로젝트의 대화 목록 표시.
  • 대화 행에 마우스를 올리면 이름 변경·삭제 아이콘이 뜬다(편집 가능 역할만).

F-04 프로젝트 / 대화 생성

API입력비고
POST /api/projects{ title }UI 기본값 "새 프로젝트"
POST /api/conversations{ project_id, title }UI 기본값 "New Chat"

viewer는 "New project" / "New chat" 버튼이 disabled. 대화 제목은 첫 메시지 전송 시 자동 갱신된다.

F-05 대화 이름 변경 / 삭제

  • PATCH /api/conversations/{id} — 제목 변경.
  • DELETE /api/conversations/{id} — 대화와 그 메시지만 삭제. 프로젝트 Stage에 이미 추가된 위젯은 유지된다.
  • 활성 대화를 삭제하면 남은 대화 목록의 첫 번째로 자동 전환.

F-06 대화 상세

GET /api/conversations/{id} — 메시지 배열 반환. assistant 메시지는 artifact JSON을 포함한다.

채팅 (에이전트)

기준일 2026-09-21 (구현 기준) · 코드: agent_service.py, agent.py, llm.py, query.py, documents.py, message_embeddings.py

F-07 고객 DB 선택

사이드바 "Database" 셀렉트. 목록은 GET /api/database-connections(테넌트 공유). 선택한 connection_id에 따라 샘플 질문이 바뀐다.

F-08 채팅 (핵심 흐름)

입력conversation_id, message, connection_id(선택)
처리user 메시지 저장 → 제목 갱신 → 에이전트 실행 → assistant 메시지 + artifact 저장
출력user_message, assistant_message, artifact, meta, related_messages, embedding_provider, embedding_error
타임아웃150초 — 실 LLM 응답 + SQL 재시도(1회) 여유

채팅 응답은 항상 실 LLM 호출로만 만든다. 키가 없거나 호출이 실패하면 추측으로 대신 답하지 않고 에러를 그대로 올린다 — 예전에 있던 SOC/Global 키워드 매칭 폴백(run_mock_agent)은 2026-09-22 완전히 삭제됐다. 다른 커넥션(Northwind, SKAX NMS 등)에는 애초에 대응하지 못한 채 SOC 안내문을 잘못 보여주는 문제가 있었기 때문.

에이전트 실행 경로

  1. 연결/권한 해석 — 선택된 연결과 사용자 role의 table_permissions 조회. 비어 있으면 SOC/Global 기본 테이블로 폴백.
  2. 스키마 텍스트 구성 — 선택된 연결의 허용 테이블만으로 스키마 텍스트를 만든다.
  3. LLM 호출 — 플랜이 비면(키 없음/호출 실패/파싱 실패 등 사유 무관) 바로 AgentRunError를 던져 HTTP 502 + 실제 에러 메시지를 그대로 반환한다.
  4. SQL 실행 — 플랜이 있으면 각 위젯의 SQL을 읽기 전용 실행 → 결과를 컴포넌트별 props로 변환.
  5. 1회 복구 재시도 — SQL/JSON 실행이 실패하면 실패 사유를 repair_hint로 넣어 LLM에 재요청. 그것도 실패하면 (Mock 폴백 없이) AgentRunError를 던진다.
  6. 문서 근거 보강 — "공격"/"attack" 키워드가 있으면 DocumentProvider로 관련 문서를 찾아 해결 방안 + 출처 위젯 추가. 출처 없으면 지어내지 않는다.
  7. 사용량 기록 — 실 LLM 호출마다 llm_usage에 provider/model/토큰/성공여부 기록.

LLM 프로바이더

지원OpenAI-compatible, Gemini(OpenAI 호환 엔드포인트로 매핑, 기본 모델 gemini-3.6-flash) — 둘 다 llm._post_openai_compatible() 하나를 공유
런타임 오버라이드브라우저 Admin "AI 연결" 설정이 요청 헤더로 전달되면 서버 .env보다 우선
실패 시키가 없거나 호출이 실패하면 HTTP 502 + 실제 에러 메시지를 그대로 노출. 조용한 폴백 없음
스키마 컨텍스트선택 연결의 허용 테이블에 한해 컬럼·PK/FK를 프롬프트에 전달. 실제 데이터 행·비밀번호는 전달 안 함

SQL 규칙

  • SELECT 또는 WITH로 시작, 단일 문장만.
  • 쓰기·DDL·권한 키워드(INSERT/UPDATE/DELETE/DROP/…)가 있으면 거부.
  • FOR UPDATE/FOR SHARE 락 절 금지.
  • FROM/JOIN 대상 테이블은 역할별 허용 목록에 있어야 함.
  • 읽기 전용 커넥션, statement_timeout 기본 10초, 결과 최대 1000행.

예상 질문 유사도 DB 완료

AI가 선택한 DB의 전체 테이블에서 다양한 예상 질문과 SQL·위젯을 생성하고, 코드는 실행 가능한 읽기 전용 SQL만 검증해 저장한다. 유사 질문의 계획을 LLM 답변 생성에 전달하며 결과는 meta.question_retrieval에 포함한다. 생성 개수는 고정하지 않으며 역할별로 생성하지 않는다. 상세 문서.

채팅 메시지 임베딩 진행중

메시지를 보내면 임베딩(Gemini gemini-embedding-001 또는 OpenAI text-embedding-3-small)을 만들어 chat_vector DB(pgvector)에 저장하고, 코사인 유사도로 과거 메시지 상위 5개를 related_messages로 반환한다. 응답의 embedding_provider 필드로 실제 어떤 provider가 쓰였는지("gemini"/"openai"/"mock") 항상 명확히 알 수 있다.

주의: related_messages/embedding_provider/embedding_error는 API 응답에는 있지만 프론트가 아직 렌더링하지 않는다 — 백엔드 스캐폴드만 완료된 상태.

F-09 Artifact 표시

  • Artifact가 있으면 Widget / JSON 세그먼트 토글이 뜬다.
  • Widget 뷰: 위젯마다 제목, 렌더러, (가능하면) SQL 보기 토글, "Add to stage" 버튼.

  • 미리보기 카드는 드래그 가능(SQL 보기 중이거나 viewer면 제외).

Stage (핀보드)

기준일 2026-09-21 (구현 기준) · 코드: stages.py, StageCanvas.jsx

Stage는 프로젝트당 정확히 1개인 핀보드다. 채팅에서 나온 위젯을 사용자가 직접 배치·저장한다 — 에이전트가 완성된 대시보드를 자동 생성하지 않는다.

F-10 Stage에 위젯 추가

드래그(application/x-agent4any-widget MIME) 또는 "Add to stage" 버튼, 둘 다 POST /api/projects/{id}/stage/widgets로 귀결.

  • component가 화이트리스트 밖이면 400.
  • 합성 위젯(BarTable/PieTable/KpiSparkline)은 기본 w:6 h:7, 그 외는 w:4 h:4.
  • source_widget_id/source_artifact_id로 출처 추적.

F-11 Stage 배치 / 저장

  • 프로젝트당 Stage 1행, 없으면 GET 시 생성.
  • react-grid-layout(12열, rowHeight 36, compactType vertical).
  • 이동·리사이즈는 500ms 디바운스 후 변경된 위젯만 PATCH 저장.
  • 저장 상태(대기/저장 중…/저장됨/저장 실패)는 전역 슬롯에 있으며 readOnly에는 표시하지 않는다.

데이터 모델

stages(id, project_id UNIQUE, tenant_id, user_id, updated_at)
stage_widgets(
  id, stage_id, source_widget_id?, source_artifact_id?,
  component, title, props jsonb,
  layout_i, layout_x, layout_y, layout_w, layout_h, updated_at
)
서버 쪽에서 Stage 쓰기 API는 소유자 검사만 하고 role은 별도로 검사하지 않는다 — readOnly는 프론트 렌더링 제어일 뿐이다(Viewer 문서 참고).

F-12 Viewer 화면

  • 경로: /p/{projectId}/view. 누구나 갈 수 있는 읽기 전용 뷰(admin도 "Open viewer" 링크로 들어간다).
  • StageCanvas를 readOnly + variant="orion"으로 감싸는 얇은 페이지.
  • 헤더: Editor로 복귀, Stage 제목, 기간 pill(표시용, 실제 필터 아님), 사용자 이메일, Sign out.

F-13 DB 연결 관리

API기능권한
GET /api/database-connections연결 목록(비밀번호 비노출)로그인
POST /api/database-connections연결 추가admin
POST .../testSELECT 1 연결 테스트로그인
GET .../tables베이스 테이블 목록로그인
POST .../preview-sql검증된 SELECT 실행admin

비밀번호는 APP_SECRET 기반 Fernet 암호화로 저장, 조회 응답에는 절대 포함하지 않는다.

F-14 테이블 권한

PUT /api/table-permissions { connection_id, role, tables }로 특정 역할의 허용 테이블 전체를 delete-then-insert로 교체한다. 현재 Admin UI는 user 역할만 편집 가능.
